How it works

So, what does Clipped actually do?

The short version, without the technical parts.

You install it once

Two commands inside Claude Code. Nothing to set up per project. In a project without a board, Claude asks once before starting one.

Every session starts with a recap

When you open Claude Code in a project, Claude reads that project's board first: what's in progress, what's parked, and what's waiting for you.

Claude notices what you're doing

Building a feature, fixing a bug, asking a question, thinking out loud. Claude recognizes which one it is and writes it on the board right away.

It remembers where you stopped

When you switch topics or call it a day, the card is parked with a short note on where you left off and what comes next.

You stay in charge

When Claude isn't sure, a card lands in Your turn. It only moves to Done when you say so, or when the work is merged or deployed. You can change anything on the board yourself.

It stays on your computer

The board is a single file inside your project. Nothing is uploaded, and there is no account.

The rules

What counts as what

One line sits under all of it: work has a next step, notes don't. Claude applies the rest for you — this is here for the day you disagree with a call it made, and want to know what it was aiming at.

Cards — things with a next step

Feature
A user-visible outcome that takes more than one reply to build. If it lands in a single reply, it's a step inside another card, or nothing at all.
Bug
Something that used to work, or that you called broken. Same card, different label — it still needs a next step and an end.
Chore
Work with nothing for you to look at afterwards: a cleanup, a config change, a job to run. Unticked boxes in a plan usually land here.
Question
Something to go and find out before you can decide — a price, a library, what a spec allows. Claude records what it found; deciding stays yours.

Notes — the thinking around it

Brainstorm
A conversation that reached a decision. The body says what was decided, not everything that was said — one per conversation, linked to the cards it produced.
Plan
A spec or plan document you wrote. The document keeps the reasoning; the board only tracks what came of it.
Reference
A link you'd look up twice, tied to the card it informed. Not every link that went past — only the ones that were actually used.

Idea is not a type — it's a status. A feature, a bug, a chore and a question all start there when you mention them in passing: it means nobody has picked it up yet.

How it decides, each time you ask for something

  1. 1Is this about a card that's already open — same topic, same files? Then it updates that card instead of opening another one.
  2. 2Will it take more than one reply, or touch several files? That's a new card, named the way you'd say it, not the way the code is organised.
  3. 3Anything smaller becomes a step on the card you're already on — or nothing at all.

Chat isn't recorded, and neither is a question Claude answers in the same breath. Brainstorming records nothing until the conversation lands on something concrete — then it offers the list once, in your words, and drops it if you say no. Ask for three things at once and you get three cards: the one being worked on is In progress, the rest wait in Idea.

What it is

What it does, and what it doesn't

I'd rather you know the limits before you install it.

It does

  • Keeps the board without being askedClaude opens a card when real work starts, adds steps, and moves the card along as the work goes.
  • Remembers where you stoppedParking a card needs a note saying where you stopped, so picking it up weeks later is cheap.
  • Briefs Claude at the start of every sessionClaude already knows what's open, parked and waiting for review before you type anything.
  • Shows every project in one placeboard ui opens a local page listing every repo that has a board, and it updates live.
  • Keeps notes you'd lose in the chatBrainstorms, plans and references get their own tabs next to the cards.

It doesn't

  • Close cards on a guessWhen Claude isn't sure, a card lands in Your turn. It only moves to Done when you say so, or when the work is merged or deployed.
  • Touch your gitNo commits, no pushes, no branches. It writes one file: .board/board.json.
  • Send your work anywhereNo account, no cloud copy. The board is a file in your repo. Details below.
  • Leave boards everywhereA project gets a board the first time something in it is worth keeping. Your home folder and hidden folders never get one.
  • Work for teamsIt's for one person on one machine. There's no sharing, no sync and no assignees.

Under the hood

What runs on your machine, and what Claude sees

Three short hooks you can read, and the brief they put in front of Claude every time a session starts.

HookWhat happens
SessionStarta session starts Reads the board and adds a short summary to Claude's context. This costs tokens: a few hundred for a small board, about 750 for this repo's 19 cards.
PostToolUseafter Claude edits a file Attaches the file path to the active card, but only when the file plausibly belongs there. No output and no extra tokens.
StopClaude finishes a turn If code changed but the board didn't, Claude is asked once to update it or say why not. This adds one short step to that turn at most, and never loops.
board uionly when you type it Starts a local server on localhost:4747 for the board page.

There's also a skill: the written rules Claude follows about when to open, update, park or close a card. Read the skill and the hooks.

What Claude sees when a session starts

The SessionStart hook puts a short brief in front of Claude before you type anything: what's parked and where it stopped, and what's in progress with its next step.

So when you say something vague like "the csv import thing", Claude knows which card you mean. It picks the work up there and ends its turn with one line saying what moved on the board.

Honest status

Where it's still rough

It's early. I use it every day on three projects, and this is what still goes wrong.

  • Sometimes it files work on the wrong card.Claude can attach unrelated work to whichever card is open. The rules are better now but not perfect.
  • Sometimes it forgets.Mostly after small fixes. The end-of-turn nudge catches most cases.
  • It has opinions about what counts as a card.A card is work with a next step, so one-line fixes stay off the board. That's deliberate, but you may disagree.
  • It only runs on macOS so far.It should work on Linux. Windows is untested.

Questions

Before you install

Does it cost tokens?

A little. The brief at the start of a session is a few hundred tokens for a small board, about 750 for this one. The end-of-turn nudge adds one short step only when the board fell behind.

Does it matter what language or stack I use?

No. The board tracks the work, not the code, so it works in any project Claude Code works in.

Can I edit the board myself?

Yes. Add, move or rewrite cards in the board page, or just tell Claude. Both write through the same code, so nothing gets out of sync.

What if Claude puts something on the wrong card?

Tell it, or fix it in the board page. Files can be detached from a card with board update --unfile. The rules get tighter every time I catch one of these.

Should I commit .board/board.json?

Your call. It's plain JSON. Commit it to keep the history with the code, or add it to .gitignore to keep it to yourself.

Does it need an internet connection?

No. The board, the page and the commands all run on your machine.

Two ways to install

You need Claude Code and Node 20 or newer. Both do exactly the same thing. First time with plugins? The install guide walks through every screen, and what to do when something doesn't show up.

Ask for it

  1. 1Install the Clipped plugin from avivalushai/clipped
  2. 2Approve the two commands Claude runs.
  3. 3Restart Claude Code, open a project and work as usual.

Works wherever Claude Code runs — the desktop app, a terminal, your editor.

Type it yourself

  1. 1/plugin marketplace add avivalushai/clipped
  2. 2/plugin install clipped@clipped
  3. 3Restart Claude Code, open a project and work as usual.

Inside Claude Code in a terminal or editor, not in your shell — the first line says where to look, the second installs from it. The desktop app has its own plugin menu: see the guide. From a shell, one line does both: claude plugin marketplace add avivalushai/clipped && claude plugin install clipped@clipped

Your first ten minutes

  1. 1Set up a board for this project from my recent commits and open branches
  2. 2Written a spec? /clipped:plan docs/plan.md turns it into cards, and shows you the list before adding any.
  3. 3board ui lists every project you've worked in with Claude Code. Click the ones worth a board.

All optional — the board fills as you work either way. This is how you start from what you already did.

Uninstall

  1. 1/plugin uninstall clipped@clipped
  2. 2Optional: delete .board/ in your projects and ~/.clipped/.

Nothing else is left behind.
